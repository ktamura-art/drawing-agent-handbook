どう動くか

担当者がやることは「依頼を1行足す」だけです。 図面と対象を選んで保存すると、1分以内に処理が始まります。

終わると状態が「完了」に変わり、判定シートに結果が1項目1行で並びます。 画面では、確認済みのチェックとコメントだけを書き込みます。

AppSheet から直接 Apps Script を呼ばない理由

ここが設計の分かれ目です

AppSheet には実行時間の上限があります。

区分AppSheet 上の呼び名上限
アプリの操作をきっかけにした実行app event2 分
時刻をきっかけにした実行schedule event5 分

出典: AppSheet ヘルプ「Automation limits」

こちらで測った実測は、5ページの図面で工程1〜3が1分10秒でした。 2分に対して余裕がありません。ページ数の多い図面では確実に超えます。
そのため AppSheet には「依頼を1行足す」ことだけをさせ、 重い処理は Apps Script 側のトリガーに任せます。

onEdit トリガーも使いません。 「依頼が追加されたら動く」を onEdit で作りたくなりますが、動きません。 AppSheet からの同期では onEdit は発火しないためです。 Google 自身が、時間指定のトリガーを使うよう案内しています。

出典: AppSheet ヘルプ「Google スプレッドシートのデータを使用する」― 「onEdit トリガーは、データが編集され、AppSheet を介してスプレッドシートに 同期されている場合には、実行されません」

手順1　シートを作る

Apps Script でボタンを押すだけ

コードを最新版に貼り替えてから、setupAppSheetSheets を実行します。 チェック項目表と同じスプレッドシートに、4つのシートができます。

シート誰が書くか内容
図面Apps Script図面フォルダにあるPDFの一覧。選択肢に使う
依頼AppSheet が追加 → Apps Script が状態を書き戻す1行＝1回の依頼
判定Apps Script1行＝1チェック項目。確認済みとコメントだけ担当者が書く
品番Apps Script1行＝1品番。同上

従来の「チェック結果」シートはそのまま残ります。用途が違います。 あちらは帳票（毎回上書き）、こちらは台帳（追記）です。 AppSheet が読むのは新しい4シートのほうです。

手順2　アプリを作る

  1. appsheet.com にアクセスし、Workspace のアカウントでログインする
  2. My Apps ページで ＋ Create → 自分のデータから始める を選ぶ
  3. チェック項目表のスプレッドシートを選ぶ
  4. アプリエディタが開く。最初のシートがテーブルとして取り込まれる
  5. 左メニューの Data → ＋ Add new table で 「図面」「依頼」「判定」「品番」の4つを足す

取り込む順番は 図面 → 依頼 → 判定 → 品番 にしてください。 依頼は図面を参照し、判定と品番は依頼を参照します。 参照される側が先に無いと、参照の設定ができません。

確認済みと担当コメント以外は、Editable? を off にしてください。 Apps Script が書く列を担当者が上書きすると、 次の実行結果と食い違って原因が追えなくなります。

品番テーブル

判定テーブルと同じ考え方です。1点だけ違います。
URL 列と旧品番照会列は、型を Url にしてください。 押すとメーカーのページが開きます。Text のままだと文字列として出るだけです。

図面テーブル

図面IDをキーにし、ファイル名に LABEL を付けてください。 これが無いと、依頼フォームの選択肢にIDの文字列が並びます。

フォルダから消えた図面は、行を残したまま「有効」欄が空になります。 選択肢に出したくない場合は、依頼テーブルの図面ID列の Valid If に 次を入れてください。

SELECT(図面[図面ID], [有効] = "○")

手順5　トリガーを付けて、通知する

第4段階
  1. Apps Script で installPendingTrigger を実行する
  2. 1分ごとに runPending が動くようになる
  3. 先ほど出した依頼の状態が、受付 → 処理中 → 完了 と変わることを確認する
  4. 図面フォルダにPDFを足したときは refreshDrawings。毎朝そろえるなら installDrawingsTrigger

通知は AppSheet 側で作るのが簡単です。コードは要りません。 Automation で Bot を作り、 きっかけを「依頼テーブルの行が更新されたとき」、 条件を「状態が 完了 または エラー に変わったとき」にして、 メールか Google Chat を送ります。

Workspace Studio で作ることもできますが、この用途では AppSheet の Bot のほうが素直です。 依頼を出した本人が誰かを、AppSheet 側は知っているためです。

関数いつ実行するか何が起きるか

つまずきやすい点

こちらで実際に当たったものだけ
依頼を出しても、いつまでも状態が変わらない

「状態」列の初期値が「受付」になっていません。AppSheet の Data → Columns → 状態 → Initial value を確認してください。つまずくとしたら、まずここです。

トリガーを作るところで権限エラーになる

appsscript.json に script.scriptapp が入っていません。今回から増えた権限です。前回のままだと必ず出ます。

Vertex AI の呼び出しが HTTP 403 になる

appsscript.json を差し替えていません。cloud-platform の権限はコードから推測されないため、明示が要ります。

図面の選択肢が空になる

図面フォルダのIDが未設定です。setupProperties を実行してください。コードを貼り直したあとは、もう一度実行が要ります。

図面の選択肢にIDが並ぶ

図面テーブルの「ファイル名」に LABEL が付いていません。

品番のURLが押せない

URL 列の型が Text のままです。Url に変えてください。

状態が「処理中」のまま止まる

Apps Script の6分制限に当たった可能性があります。ページ数の多い図面は、ページを指定して1ページずつ依頼してください。

品番の一部が「未確認」になる

時間切れです。もう一度同じ依頼を出すと、その分を調べ直します。

この作りの限界

先に申し上げておきます

依頼から結果が出るまでに、最大1分の待ちが入ります。 押した瞬間に結果が出る作りではありません。 これは AppSheet の実行時間の上限を踏まないための設計です。

図面上の位置は出しません。 品番の検出そのものは実測で11番号中10箇所・誤検出0でしたが、 位置の特定は3×3分割で75%にとどまっています。 4件に1件外れる案内は、無いほうがましだと判断しました。 位置を取る処理自体は動いているので、精度が上がれば足せます。
