Gemini Enterprise Agent Platform

GUIでエージェントを作る

Google Cloud コンソールの Agent Studio を使い、コードを書かずに エージェントを組み立ててデプロイするまでの手順です。 記載はすべて公式ドキュメントを開いて読んだ内容によります。各項に出典を付けています。

はじめに押さえること

名前が変わりました

「Vertex AI Agent Engine」という名称はもう使われていません。 現在は Gemini Enterprise Agent Platform の中の Agent Runtime です。

APIのリソース名だけは ReasoningEngine のまま残っています。 下位互換のためと明記されています。エージェント ランタイム・2026-08-08

東京で使えます

asia-northeast1（東京）は v1 が一般提供（GA）としてサポートされています。

ランタイム・セッション・メモリバンク・Agent Gateway のいずれも対象です。 東京には「メモリバンク対象外」「Agent Gateway 対象外」の 注記が付いていません。Agent Platform のエージェントでサポートされているロケーション・2026-08-08

作る画面はプレビュー扱いです

Agent Runtime は東京でGAですが、Agent Studio の設計機能は プレビュー（pre-GA）です。「現状のまま」提供され、 サポートが限られることがあると明記されています。Agent Studio でエージェントを設計する・2026-08-08

本番運用の判断材料として、ここは押さえておく必要があります。

構成ファイルは us-west1 に保存されます

デプロイ先は東京を選べますが、 作成したエージェントの構成ファイルは us-west1 に保存されます。

組織のポリシーでこのリージョンの使用が禁止されている場合、 エージェントを作成できないことがあります。Agent Studio でエージェントを設計する・2026-08-08

作り方は3つあります

このページで扱うのは一番上のローコードです
やり方書くもの向いている場面
Agent Studio（ローコード）コードなし。画面で組む 迅速なプロトタイピング、業務中心のエージェント
Managed Agents APIREST。構成で組む サンドボックス環境での自律エージェント
ADKPython 複雑なマルチエージェント。ロジックを細かく制御する

GUIでの手順

リンクはすべてクリックできます
01

権限を付ける

Agent Studio を使う人に Agent Platform ユーザー（roles/aiplatform.user）を付けます。オーナー権限は要りません。

https://console.cloud.google.com/iam-admin/iam

「アクセスを許可」→ アカウントを入力 → ロールに「Agent Platform ユーザー」→ 保存

この1つだけで Agent Studio は使えます。 Agent Studio でエージェントを設計する・2026-08-08

02

エージェント一覧を開く

Google Cloud コンソールの［エージェント］ページです。ここが入口になります。

https://console.cloud.google.com/agent-platform/agents

上部のプロジェクト名が目的のものか、必ず確認する

作成済みのエージェントが並びます。初回は空です。 Agent Studio でエージェントを設計する・2026-08-08

03

エージェントを作成する

［エージェントを作成］を押すと、Agent Studio のキャンバスが開きます。ここが視覚的にワークフローを組む画面です。

https://console.cloud.google.com/agent-platform/studio/agent-designer/

［エージェントを作成］→ Agent Studio キャンバス

タブは2つ:
  フロー     … ワークフローと制御ロジックを組む
  プレビュー … その場でチャットして試す

エージェントをクリックすると［詳細］パネルが開きます。 Agent Studio でエージェントを設計する・2026-08-08

04

詳細パネルを埋める

メインエージェントと、必要ならサブエージェントを構成します。サブエージェントは［サブエージェントを追加］（＋）で足せます。

名前          エージェントを識別する名前
説明          目的の概要
カスタム指示  エージェントをガイドする指示文
モデル        使うモデルを選ぶ
ツール        ［ツールを追加］（＋）

「カスタム指示」が、いまGASで固定している指示文にあたります。 Agent Studio でエージェントを設計する・2026-08-08

05

ツールを選ぶ

選べるツールは4種類だけです。ここが今回の分かれ目になります。

Google 検索              既定でオン。ウェブ検索
URL コンテキスト          既定でオン。プロンプト内のURLを分析
Agent Platform Search    データストアに入れた情報を検索
MCP サーバー              外部のMCPサーバーに接続

MCPは「認証を必要としないサーバーのみ」対応です。社内システムに繋ぐ場合はここが制約になります。 Agent Studio でエージェントを設計する・2026-08-08

06

保存する

保存していないエージェントにはIDが無く、プレビューもデプロイもできません。初回だけ手で保存すれば、以降は自動保存されます。

［保存］→ エージェント名を入力 →［保存］

初回保存後は、変更が自動で保存されます。 Agent Studio でエージェントを設計する・2026-08-08

07

プレビューで試す

［プレビュー］タブで、実際にチャットして動きを確かめます。デプロイ前にここで詰められます。

［プレビュー］タブ → チャットして確認

［コードを取得］→ エージェントのコードを表示・コピー

［コードを取得］でコードを持ち出せます。GUIで組んで、続きをコードで作る、という進め方ができます。 Agent Studio でエージェントを設計する・2026-08-08

08

デプロイする

エージェント一覧から対象を選び、［デプロイ］を押します。デプロイのたびに新しいランタイム インスタンスが作られます。

https://console.cloud.google.com/vertex-ai/agents/agent-engines

［エージェント］一覧 → 対象をクリック →［デプロイ］
  →［Agent Runtime インスタンスにデプロイ］
  → リージョンを選ぶ（東京 asia-northeast1 が選べます）
  →［デプロイ］

完了まで最大5分かかります。成功すると［フロー］タブにメッセージが出ます。 Agent Studio でエージェントを設計する・2026-08-08

09

動いているか見る

デプロイ済みのエージェントは Agent Platform ページに並びます。リージョンで絞り込めます。

https://console.cloud.google.com/vertex-ai/agents/agent-engines

［リージョン］で絞る → エージェント名をクリック
  → ［指標］ページが開く
  → ［プレイグラウンド］タブでテストクエリを入れる

ここで返事が返れば、外部アプリからも呼べる状態です。 Agent Studio でエージェントを設計する・2026-08-08

今回の図面チェックは、GUIだけでは組めません

ツールが上の4種類に限られるため、いまGASで動かしている処理は GUIの中に置き換えられません。何ができて何ができないかを、 機能ごとに分けます。

いまの機能GUI理由
図面PDFをドライブから取り出す×ツールに Drive を読む手段がありません。Agent Platform Search のデータストアに入れれば検索はできますが、PDFを1枚渡して位置つきで読ませる用途とは別です。
図面を読み取って位置を返す△モデル自体はPDFを読めますが、Agent Studio の画面からファイルを渡す経路が用意されていません。
チェック項目表（スプレッドシート）を読む×スプレッドシートを読むツールがありません。MCPサーバーを自前で立てれば繋げますが、「認証なしのサーバーのみ」という制約が付きます。
メーカー公式ページを見に行く△URL コンテキストで読ませることは可能です。ただしリピートの値はページの静的HTMLがミリメートル表記のため、モデルに読ませると10倍になります。コードで取る必要があります。
根拠が実在するか突き合わせる×文字列の照合はコードの仕事です。GUIには書く場所がありません。AIに自己検証させると、実在しない文言をそのまま通します。
結果をスプレッドシートに書き出す×書き出すツールがありません。

それでも見せる価値はあります

Agent Studio で作れるのは、「作図基準について答える対話型エージェント」 までです。作図マニュアルをデータストアに入れれば、 「電気図の縮尺は」と聞いて答えさせることはできます。

当日はこれを別物としてお見せするのが誠実です。 「図面チェックがGUIで作れる」と説明すると、その場で作れずに終わります。

［コードを取得］でコードを持ち出せるので、 GUIで骨組みを作り、続きをコードで仕上げるという進め方は可能です。

では、Agent Studio で何が作れるのか

4つのツールの範囲で、実務に効くもの

図面チェックは組めませんが、作れて役に立つものはあります。 下の3つは、いずれも Agent Studio だけで完結します。 指示文はそのまま「指示」欄に貼れる形にしてあります。

1メーカー品番の下調べ設定ゼロ・その場で作れます

既定でオンの Google 検索と URL コンテキストだけで動きます。データストアもMCPも要りません。当日その場で作って見せられます。

使うツール　Google 検索 ／ URL コンテキスト（どちらも既定でオン）

そのまま「指示」欄に貼れます
あなたは住宅の内装クロスの品番を調べる担当です。

品番を渡されたら、次の順で調べて答えてください。

1. その品番のメーカーを特定する
2. メーカー公式サイトの該当ページを探す
3. そのページに書かれているリピート（タテ・ヨコ）を読む

厳守事項:
・答えは必ずメーカー公式サイトの記載に基づく。まとめサイトや販売店は根拠にしない
・参照したページのURLを必ず示す
・公式サイトで確認できないものは「確認できませんでした」と答える。推測で埋めない
・ページに書かれている数値をそのまま引用する。自分で単位を換算しない
・現行カタログに無い品番は、旧品番の可能性を伝え、
  メーカーの新旧品番対照検索を案内する

次の形式で答えてください。
品番 ／ メーカー ／ リピート ／ 根拠にした記載 ／ 参照したURL

精度は保証できません。人が最後にURLを開いて確かめる前提の「下調べ」として使ってください。

2作図基準の質問応答マニュアルをデータストアに入れます

設計者が図面を描く前に「この場合どうするんだったか」を引ける相手になります。いまのチェックは描いた後。こちらは描く前に効きます。

使うツール　Agent Platform Search データストア（作図マニュアル6冊を投入）

そのまま「指示」欄に貼れます
あなたは自社の作図基準について答える担当です。

厳守事項:
・回答は、接続された作図マニュアルの記載だけに基づく
・該当箇所の章・節（例「6-1 基本事項(2)-2」）を必ず示す
・マニュアルに書かれていないことは「マニュアルに記載がありません」と答える。
  一般論で補わない
・建売と注文で基準が違う場合は、両方を分けて示す
・数値（縮尺・寸法・文字サイズなど）は、マニュアルの表記をそのまま引用する

質問が曖昧なときは、どの図面種別か
（平面詳細図・配置図・立面図・断面図・電気図・求積図・建具）を聞き返してください。

出典の章・節を必ず出させるのが要点です。根拠が付かない回答は、確認のしようがありません。

3チェック項目の起草支援同じデータストアを使い回せます

いちばん効きます。先方の狙いは57項目を300項目に増やすことで、その作業そのものを助けます。上の質問応答と同じデータストアで動きます。

使うツール　Agent Platform Search データストア（同上）

そのまま「指示」欄に貼れます
あなたは作図基準から、図面チェック項目の草案を作る担当です。

指定された章について、チェック項目の行を作ってください。
各行は次の6つで構成します。

  対象            全図面／平面詳細図／配置図／立面図／断面図／電気図／
                  求積図／建具（外部）／建具（内部）のいずれか
  チェック項目     「〜になっているか」の形で1文
  判定の根拠となる基準  マニュアルの記載をそのまま引用
  出典            章・節の番号
  判定可否         自動／半自動／要検討
  備考            補足があれば

「判定可否」の決め方:
  自動    図面に書かれた文字だけで判定できる
  半自動  位置関係や図形を見る必要がある
  要検討  フォントや線種など、文字として読み取れない

厳守事項:
・マニュアルに書かれていない項目を作らない
・基準は要約せず、原文を引用する
・1つの項目に2つのことを混ぜない。分ける

出力は表形式にしてください。

出てきた行をチェック項目表に貼れば、次の実行から判定に加わります。人が採否を決める前提の草案として使います。
