GCPの画面でやること

最初に一度だけ。5分ほど
リンクはすべてクリックできます。開くとGoogle Cloudの該当画面に直接飛びます。 プロジェクトを複数お持ちの場合は、画面上部で目的のプロジェクトが選ばれているか 必ず確認してください。
1

プロジェクトを選ぶ

画面上部の青いバーに、いまどのプロジェクトを開いているかが出ています。ここが目的のプロジェクトになっているか確認してください。違っていたら名前の部分をクリックして選び直します。

https://console.cloud.google.com/projectselector2/home/dashboard

プロジェクトIDを控えておいてください。あとで使います。

2

Vertex AI API を有効にする

上のリンクを開くと「Vertex AI API」のページが出ます。青い「有効にする」ボタンを押してください。すでに有効な場合は「管理」と表示されているので、そのままで結構です。

https://console.cloud.google.com/apis/library/aiplatform.googleapis.com

これが図面を読ませるための本体です。Apps Script からこのAPIを呼びます。

3

課金アカウントを紐づける

左メニューの「お支払い」を開きます。このプロジェクトに課金アカウントが紐づいていないと、APIを呼んだ時点でエラーになります。「請求先アカウントをリンク」から設定してください。

https://console.cloud.google.com/billing

図面1枚あたり1〜3円程度です。無料枠の範囲で試せます。

4

操作する人に権限を付ける

左メニューの「IAMと管理」→「IAM」を開きます。「アクセスを許可」を押し、担当者のGoogleアカウントを入力して、ロールに「Vertex AI ユーザー」を選んで保存します。

https://console.cloud.google.com/iam-admin/iam

オーナー権限は不要です。読み取りと実行だけで動きます。

5

動いているか確かめる

左メニューの「Vertex AI」→「Vertex AI Studio」を開き、何か文章を入れて返事が返ってくるか見てください。ここで返事が返れば、プログラムからも呼べる状態です。

https://console.cloud.google.com/vertex-ai

返らない場合は、2〜4のどれかが未完了です。

エージェントはどこにあるのか

いまの形 ― 作る必要はありません

エージェントの実体は手元のプログラムです。 GCPの画面に「エージェント」という項目が増えるわけではありません。

GCP側は、そのプログラムからGeminiを呼ぶことを許可しているだけです。 画面で作るものは何もなく、上の1〜4を済ませれば動きます。

外部のシステムから呼びたい場合

「別のシステムからAPIで呼びたい」という場合は、 エージェントをGoogle Cloudに置きに行く作業が必要になります。

Vertex AI は Gemini Enterprise Agent Platform に統合され、 ADKで作ったエージェントは agents-cli deploy で配置できます。 配置するとURLが発行され、そこに対して呼び出せるようになります。

この配置はまだ行っていません。必要になった時点で進めます。

組み立ての手順

ブラウザだけで完結します。1回だけ30分ほど
01

だれが何をするのか

業務でお使いになる方は、コマンドもコードも触りません。公開されたURLを開いて、図面を選ぶだけです。以下は、仕組みを最初に組み立てる方が1回だけ行う作業です。

業務担当者   … ブラウザでURLを開く。それだけ
組み立てる方 … 以下を1回だけ実施する（30分ほど）

パソコンに入れるものはありません。ブラウザだけで完結します。

02

コードを貼り付ける

Apps Script の新規プロジェクトを開き、お渡しするコードを貼り付けます。script.new を開くと空のプロジェクトが作られます。

1. https://script.new を開く
2. 既定の myFunction ごと消す
3. お渡しした「コード.gs」の内容をすべて貼り付ける
4. 保存する（Ctrl + S）

左のファイル一覧に「コード.gs」があれば成功です。

03

権限の指定を差し替える

コードを貼っただけでは、AIを呼ぶ権限が付きません。設定ファイルに明示する必要があります。ここを飛ばすと必ず失敗します。

1. 左メニューの ⚙プロジェクトの設定 を開く
2.「appsscript.json マニフェスト ファイルをエディタで表示する」に
   チェックを入れる
3. エディタに戻ると appsscript.json が現れるので、
   お渡しした内容に差し替えて保存する

飛ばすと「HTTP 403 insufficient authentication scopes」で止まります。コードから権限は推測されないため、必ず明示します。

04

設定を保存する

使うGCPプロジェクトと、チェック項目表の場所を登録します。画面上部の関数名から setupProperties を選んで実行するだけです。

上部のプルダウン → setupProperties → ▶実行

登録される内容:
  GCP_PROJECT_ID     使用するGCPプロジェクト
  VERTEX_LOCATION    asia-northeast1（東京）
  ITEMS_SHEET_ID     チェック項目表
  DRAWING_FOLDER_ID  図面を置くフォルダ

実行ログに「設定を保存しました。」と出れば成功です。

05

動作を確認する

公開する前に、1枚だけ試します。初回は権限の承認画面が出るので、内容を確認して許可します。

上部のプルダウン → runCheck → ▶実行

承認画面が出たら:
  権限を確認 → アカウントを選択 →
  「詳細」→「プロジェクトに移動」→ 許可

自作のスクリプトのため、確認されていないアプリとして表示されます。1〜3分で結果が出ます。

06

社内に公開する

ウェブアプリとして公開します。URLが1つ発行され、自社のアカウントを持つ方なら誰でも開けるようになります。

1. 右上の「デプロイ」→「新しいデプロイ」
2. 歯車アイコン →「ウェブアプリ」を選ぶ
3. 次のように設定する
     次のユーザーとして実行  自分
     アクセスできるユーザー  <自社ドメイン>内の全員
4.「デプロイ」を押す

発行されたURLが、担当者に配るものです。社外の方はログインしても開けません。

07

担当者に配る

配るのはURLだけです。担当者側の準備は要りません。図面を選んで「確認する」を押すと、結果が画面に出ます。

https://script.google.com/a/macros/<ドメイン>/s/……/exec

結果はスプレッドシートの「チェック結果」タブにも残ります。

08

項目を増やす・減らす

チェック項目はスプレッドシートから毎回読み込んでいます。行を足せば次の実行から判定され、「採用」列に × を入れればその項目は外れます。

チェック項目表を開いて、行を足す／× を入れる

→ コードの修正も、再公開も不要

1項目ずつ開発していては費用が見合わないため、ここが要点になります。

途中で起きた失敗

同じところで詰まるため、残しています

URLをモデルに答えさせていた

10件中6件が google.com/search?q=… という検索エンジンのURLになった。人が後で確認するためのURLなのに、Google検索に飛ばすだけでは確認にならない。

直し方 品番の形からメーカーを判定し、コードがURLを組み立てる形に変えた。検索エンジンのURLはゼロになった。

検証が甘く、10件すべてが確定に見えた

URLと根拠が「空でないこと」しか見ていなかったため、検索エンジンのURLでも確定として通っていた。

直し方 メーカーの商品ページに到達したものだけを確定とした。結果は 確定4件 / 要確認6件。こちらが実態。

権限の指定が足りず、AIを呼べなかった

コードを貼り付けただけでは cloud-platform の権限が付かず、HTTP 403 insufficient authentication scopes で止まった。Apps Script はコードから使う権限を推測するが、外部リクエストの先までは分からない。

直し方 設定ファイル（appsscript.json）に権限を明示した。手順にもその工程を入れ、飛ばせないようにした。

結果の書き出しで落ちた

表に書き込む際、空行だけ列数が0で、「データの列数と範囲の列数が一致しません」で止まった。判定そのものは終わっていたのに、結果が残らなかった。

直し方 書き込む直前に全行の列数を揃える処理を入れた。原因の行を直すのではなく、以後どんな行が来ても揃うようにした。

ループが指定回数まで空回りしていた

待ち行列が尽きたときに escalate でループを抜ける実装にしたが、コールバックからイベントに伝播せず、上限まで回っていた。

直し方 抽出を先に走らせ、件数が確定してから max_iterations を決める2段構えにした。

まだできていないこと

・リリカラのURL形式は、検索フォームの形から組み立てたもので未確認です。
・旧品番の自動照会は未実装です。現状は新旧品番対照検索への誘導までです。
・社内コード（OAS-）とメーカー品番（SP-）の対応は未確定です。品番マスタが要ります。
