GCPの画面でやること

最初に一度だけ。5分ほど
リンクはすべてクリックできます。開くとGoogle Cloudの該当画面に直接飛びます。 プロジェクトを複数お持ちの場合は、画面上部で目的のプロジェクトが選ばれているか 必ず確認してください。
1

プロジェクトを選ぶ

画面上部の青いバーに、いまどのプロジェクトを開いているかが出ています。ここが目的のプロジェクトになっているか確認してください。違っていたら名前の部分をクリックして選び直します。

https://console.cloud.google.com/projectselector2/home/dashboard

プロジェクトIDを控えておいてください。あとで使います。

2

Vertex AI API を有効にする

上のリンクを開くと「Vertex AI API」のページが出ます。青い「有効にする」ボタンを押してください。すでに有効な場合は「管理」と表示されているので、そのままで結構です。

https://console.cloud.google.com/apis/library/aiplatform.googleapis.com

これが図面を読ませるための本体です。ほかのAPIは当面要りません。

3

課金アカウントを紐づける

左メニューの「お支払い」を開きます。このプロジェクトに課金アカウントが紐づいていないと、APIを呼んだ時点でエラーになります。「請求先アカウントをリンク」から設定してください。

https://console.cloud.google.com/billing

図面1枚あたり1〜3円程度です。無料枠の範囲で試せます。

4

操作する人に権限を付ける

左メニューの「IAMと管理」→「IAM」を開きます。「アクセスを許可」を押し、担当者のGoogleアカウントを入力して、ロールに「Vertex AI ユーザー」を選んで保存します。

https://console.cloud.google.com/iam-admin/iam

オーナー権限は不要です。読み取りと実行だけで動きます。

5

動いているか確かめる

左メニューの「Vertex AI」→「Vertex AI Studio」を開き、何か文章を入れて返事が返ってくるか見てください。ここで返事が返れば、プログラムからも呼べる状態です。

https://console.cloud.google.com/vertex-ai

返らない場合は、2〜4のどれかが未完了です。

エージェントはどこにあるのか

いまの形 ― 作る必要はありません

エージェントの実体は手元のプログラムです。 GCPの画面に「エージェント」という項目が増えるわけではありません。

GCP側は、そのプログラムからGeminiを呼ぶことを許可しているだけです。 画面で作るものは何もなく、上の1〜4を済ませれば動きます。

外部のシステムから呼びたい場合

「別のシステムからAPIで呼びたい」という場合は、 エージェントをGoogle Cloudに置きに行く作業が必要になります。

Vertex AI は Gemini Enterprise Agent Platform に統合され、 ADKで作ったエージェントは agents-cli deploy で配置できます。 配置するとURLが発行され、そこに対して呼び出せるようになります。

この配置はまだ行っていません。必要になった時点で進めます。

組み立ての手順

Windows での手順。当日はこの順に進めます
01

だれがコマンドを打つのか

業務でお使いになる方は、コマンドを打つ必要がありません。できあがった画面のURLを開いて、図面を選ぶだけです。以下の手順は、仕組みを構築して社内に配る方（情報システム担当など）向けです。

業務担当者   … ブラウザでURLを開くだけ
構築する担当者 … 以下の手順を1回だけ実施する

1度構築すれば、以降は全員が同じURLを使えます。

02

PowerShell を開く

Windows の場合、コマンドはすべて PowerShell に入力します。画面左下のスタートボタンを押し、そのまま powershell と打つと「Windows PowerShell」が出るので、それをクリックして開きます。

スタートボタン → powershell と入力 → Windows PowerShell をクリック

青または黒い画面が開き、文字を入力できる状態になれば成功です。

03

Python を入れる

図面を読ませるプログラムを動かすために必要です。下のリンクからインストーラをダウンロードし、実行します。インストール画面で「Add python.exe to PATH」に必ずチェックを入れてください。ここを入れ忘れると、以降のコマンドが動きません。

https://www.python.org/ftp/python/3.13.7/python-3.13.7-amd64.exe

# 入ったことを確認する（PowerShell に入力）
py --version

Python 3.13.7 のように表示されれば成功。ADK には 3.10 以上が必要です。

04

Google Cloud CLI を入れる

GCP に接続するための道具です。下のリンクからインストーラを実行します。必要な Python は同梱されているので、追加の設定は要りません。インストール後、PowerShell を一度閉じて開き直してください。

https://dl.google.com/dl/cloudsdk/channels/rapid/GoogleCloudSDKInstaller.exe

# 入ったことを確認する
gcloud --version

Google Cloud SDK の後にバージョン番号が並べば成功です。

05

GCP にログインする

2つ実行します。1つ目は操作する人の認証、2つ目はプログラムがGCPを使うための認証です。どちらもブラウザが開くので、会社のGoogleアカウントでログインしてください。

gcloud auth login
gcloud auth application-default login

# 使うプロジェクトを指定する
gcloud config set project <プロジェクトID>

ブラウザに「認証が完了しました」と出れば成功です。

06

作業用のフォルダを作る

デスクトップに作業場所を用意し、そこへ移動します。以降のコマンドは、すべてこのフォルダの中で実行します。

cd $HOME\Desktop
mkdir zumen-agent
cd zumen-agent

画面左側の表示が …\Desktop\zumen-agent に変われば成功です。

07

プログラムの置き場を用意する

Python のプログラムを、この作業用フォルダの中だけで動かすための準備です。他のソフトに影響しません。

py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\pip.exe install google-adk fastapi uvicorn python-multipart

最後に Successfully installed … と出れば成功。数分かかります。

08

部品が入ったか確かめる

エージェントの順序を固定するための部品が使えるかを確認します。ここが通れば、環境の準備は完了です。

.venv\Scripts\python.exe -c "from google.adk.agents import SequentialAgent, LoopAgent, ParallelAgent; print('OK')"

OK と表示されれば成功です。エラーが出る場合は Python のPATH設定を見直してください。

09

プログラムを置く

弊社からお渡しするファイル一式を、作業用フォルダに展開します。agent.py（工程の定義）、makers.py（メーカー別のURL）、main.py（画面）などが含まれます。

# 配布ファイルを zumen-agent フォルダに展開する
# 展開後、中身を確認する
dir

main.py、makers.py、requirements.txt などが並んでいれば成功です。

10

手元で動かしてみる

デプロイの前に、自分のパソコンで画面を出して確認します。問題があればここで分かります。

.venv\Scripts\uvicorn.exe main:app --port 8090

# ブラウザで開く
http://localhost:8090/

図面を選ぶ画面が出れば成功。止めるときは PowerShell で Ctrl と C を同時に押します。

11

社内に配る（デプロイ）

Google Cloud に載せて、URLで開けるようにします。初回は10分ほどかかります。<プロジェクトID> は実際の値に置き換えてください。

gcloud run deploy zumen-check --source=. `
  --project=<プロジェクトID> --region=asia-northeast1 `
  --timeout=900 --memory=1Gi --no-allow-unauthenticated --iap `
  --set-env-vars=GOOGLE_GENAI_USE_VERTEXAI=TRUE,GOOGLE_CLOUD_PROJECT=<プロジェクトID>,GOOGLE_CLOUD_LOCATION=asia-northeast1

最後に Service URL: https://… と表示されます。これが社内に配るURLです。

12

社内の人が開けるようにする

初期状態では、作った本人も含めて誰も開けません。自社ドメインのアカウントに、アクセス権を付けます。反映に数分かかります。

gcloud beta iap web add-iam-policy-binding `
  --resource-type=cloud-run --service=zumen-check `
  --region=asia-northeast1 --project=<プロジェクトID> `
  --member="domain:<自社のドメイン>" `
  --role="roles/iap.httpsResourceAccessor"

反映後、社内の方がURLを開くとGoogleのログイン画面が出ます。社外の方はログインしても入れません。

途中で起きた失敗

同じところで詰まるため、残しています

URLをモデルに答えさせていた

10件中6件が google.com/search?q=… という検索エンジンのURLになった。人が後で確認するためのURLなのに、Google検索に飛ばすだけでは確認にならない。

直し方 品番の形からメーカーを判定し、コードがURLを組み立てる形に変えた。検索エンジンのURLはゼロになった。

検証が甘く、10件すべてが確定に見えた

URLと根拠が「空でないこと」しか見ていなかったため、検索エンジンのURLでも確定として通っていた。

直し方 メーカーの商品ページに到達したものだけを確定とした。結果は 確定4件 / 要確認6件。こちらが実態。

ループが指定回数まで空回りしていた

待ち行列が尽きたときに escalate でループを抜ける実装にしたが、コールバックからイベントに伝播せず、上限まで回っていた。

直し方 抽出を先に走らせ、件数が確定してから max_iterations を決める2段構えにした。

まだできていないこと

・リリカラのURL形式は、検索フォームの形から組み立てたもので未確認です。
・旧品番の自動照会は未実装です。現状は新旧品番対照検索への誘導までです。
・社内コード（OAS-）とメーカー品番（SP-）の対応は未確定です。品番マスタが要ります。
