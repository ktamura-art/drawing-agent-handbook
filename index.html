GCPの画面でやること

最初に一度だけ。5分ほど
リンクはすべてクリックできます。開くとGoogle Cloudの該当画面に直接飛びます。 プロジェクトを複数お持ちの場合は、画面上部で目的のプロジェクトが選ばれているか 必ず確認してください。
1

プロジェクトを選ぶ

画面上部の青いバーに、いまどのプロジェクトを開いているかが出ています。ここが目的のプロジェクトになっているか確認してください。違っていたら名前の部分をクリックして選び直します。

https://console.cloud.google.com/projectselector2/home/dashboard

プロジェクトIDを控えておいてください。あとで使います。

2

Vertex AI API を有効にする

上のリンクを開くと「Vertex AI API」のページが出ます。青い「有効にする」ボタンを押してください。すでに有効な場合は「管理」と表示されているので、そのままで結構です。

https://console.cloud.google.com/apis/library/aiplatform.googleapis.com

これが図面を読ませるための本体です。ほかのAPIは当面要りません。

3

課金アカウントを紐づける

左メニューの「お支払い」を開きます。このプロジェクトに課金アカウントが紐づいていないと、APIを呼んだ時点でエラーになります。「請求先アカウントをリンク」から設定してください。

https://console.cloud.google.com/billing

図面1枚あたり1〜3円程度です。無料枠の範囲で試せます。

4

操作する人に権限を付ける

左メニューの「IAMと管理」→「IAM」を開きます。「アクセスを許可」を押し、担当者のGoogleアカウントを入力して、ロールに「Vertex AI ユーザー」を選んで保存します。

https://console.cloud.google.com/iam-admin/iam

オーナー権限は不要です。読み取りと実行だけで動きます。

5

動いているか確かめる

左メニューの「Vertex AI」→「Vertex AI Studio」を開き、何か文章を入れて返事が返ってくるか見てください。ここで返事が返れば、プログラムからも呼べる状態です。

https://console.cloud.google.com/vertex-ai

返らない場合は、2〜4のどれかが未完了です。

エージェントはどこにあるのか

いまの形 ― 作る必要はありません

エージェントの実体は手元のプログラムです。 GCPの画面に「エージェント」という項目が増えるわけではありません。

GCP側は、そのプログラムからGeminiを呼ぶことを許可しているだけです。 画面で作るものは何もなく、上の1〜4を済ませれば動きます。

外部のシステムから呼びたい場合

「別のシステムからAPIで呼びたい」という場合は、 エージェントをGoogle Cloudに置きに行く作業が必要になります。

Vertex AI は Gemini Enterprise Agent Platform に統合され、 ADKで作ったエージェントは agents-cli deploy で配置できます。 配置するとURLが発行され、そこに対して呼び出せるようになります。

この配置はまだ行っていません。必要になった時点で進めます。

組み立ての手順

当日はこの順に進めます
01

環境をつくる

Python 3.14 で仮想環境を作り、ADK を入れる。ADK には順序を固定して組むための部品が含まれている。

python3.14 -m venv .venv
.venv/bin/pip install google-adk pdf2image pillow

# 入ったことを確認する
.venv/bin/python -c "from google.adk.agents import \
  SequentialAgent, LoopAgent, ParallelAgent; print('OK')"

SequentialAgent / LoopAgent / ParallelAgent が import できれば成功。

02

GCPにつなぐ

Vertex AI を東京リージョンで使う。API キーは使わず、ログイン中のアカウントの権限で動かす。

gcloud auth application-default login

export GOOGLE_GENAI_USE_VERTEXAI=TRUE
export GOOGLE_CLOUD_PROJECT=<プロジェクトID>
export GOOGLE_CLOUD_LOCATION=asia-northeast1

この3つを差し替えるだけで、別のGCPプロジェクトに向く。

03

工程1 ― 読み取る

図面PDFをそのまま Gemini に渡し、クロス品番と図面上の位置を抜き出す。画像への変換は不要。

extract_agent = LlmAgent(
    name="extract",
    model="gemini-3.5-flash",
    instruction=EXTRACT_INSTRUCTION,
    output_key="extracted",
)

抜き出すものと抜き出さないものを指示文に明記する。防火設備の認定番号など、品番と同じ形の別番号を除くため。

04

待ち行列に積む

抽出結果を Python 側の待ち行列に移す。何件あるかをモデルに数えさせない。

def build_queue(ctx):
    data = _json(ctx.state.get("extracted")) or {}
    ctx.state["queue"]  = data.get("codes", [])
    ctx.state["cursor"] = 0
    ctx.state["found"]  = []

extract_agent.after_agent_callback = build_queue

ここが「途中で力尽きる」を避ける要。件数の管理をコードが持つ。

05

メーカー別に確認先を決める

URLはモデルに答えさせない。品番の形からメーカーを判定し、コードが組み立てて、実在するかHTTPで確かめる。

resolved = makers.resolve(primary)
ctx.state["current_url"]   = resolved["url"]
ctx.state["current_maker"] = resolved["maker"]

商品詳細 → 品番検索 → 旧品番照会 の順に降りる。詳細が 404 なら現行カタログに無いということ。

06

工程2 ― 1件ずつ調べる

LoopAgent が抽出件数ぶん回る。モデルは常に1件だけを見る。件数が増えてもモデルの仕事量は変わらない。

researcher = LlmAgent(
    name="researcher",
    tools=[google_search],
    instruction=RESEARCH_INSTRUCTION,
    output_key="research_result",
)
researcher.before_agent_callback = pick_next   # 次の1件を渡す
researcher.after_agent_callback  = record      # 結果を控える

loop = LoopAgent(name="research_loop",
                 sub_agents=[researcher],
                 max_iterations=len(queue))

max_iterations は抽出できた実件数。繰り返す回数をコードが決める。

07

工程3 ― 検証する

メーカーの商品ページに到達し、そこに書かれていた記載を根拠に判定が付いたものだけを確定とする。それ以外は人に回す。

ok = (r["url_kind"] == "商品ページ"
      and r["url_verified"]
      and r["repeat"] in ("リピートあり", "リピートなし")
      and r["evidence"])

ここを緩めると「10件すべて確定」に見えてしまう。実際に一度そうなった。

08

実行する

図面PDFとページ番号を渡すだけ。

.venv/bin/python run_repeat.py <図面PDF> 2

結果は out/repeat_result.json と、画面の一覧に出る。

途中で起きた失敗

同じところで詰まるため、残しています

URLをモデルに答えさせていた

10件中6件が google.com/search?q=… という検索エンジンのURLになった。人が後で確認するためのURLなのに、Google検索に飛ばすだけでは確認にならない。

直し方 品番の形からメーカーを判定し、コードがURLを組み立てる形に変えた。検索エンジンのURLはゼロになった。

検証が甘く、10件すべてが確定に見えた

URLと根拠が「空でないこと」しか見ていなかったため、検索エンジンのURLでも確定として通っていた。

直し方 メーカーの商品ページに到達したものだけを確定とした。結果は 確定4件 / 要確認6件。こちらが実態。

ループが指定回数まで空回りしていた

待ち行列が尽きたときに escalate でループを抜ける実装にしたが、コールバックからイベントに伝播せず、上限まで回っていた。

直し方 抽出を先に走らせ、件数が確定してから max_iterations を決める2段構えにした。

まだできていないこと

・リリカラのURL形式は、検索フォームの形から組み立てたもので未確認です。
・旧品番の自動照会は未実装です。現状は新旧品番対照検索への誘導までです。
・社内コード（OAS-）とメーカー品番（SP-）の対応は未確定です。品番マスタが要ります。
